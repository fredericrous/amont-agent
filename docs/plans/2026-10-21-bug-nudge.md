# Plan: nudge the diagnosing-bugs skill from a hook

## Review panel

👉 **Decide:** the success bar (two weeks or 20 bug sessions, at least half loaded) and whether to release the assertion now or after the measurement.
📍 amont-agent · plan ready · next: approve, then build the assertion in a worktree. Panel: backend, rust, tui, unix (two rounds, all approve-with-changes after round 2; findings folded in).
**Changed by review:** trigger split (failed exit vs exit 0); marker and skill-check order; pipefail-off exit handling.
**Verdicts:** round 1 rework ×3, approve-with-changes ×1; round 2 approve-with-changes ×4. Carried into implementation: none.

## Context

The `diagnosing-bugs` skill is model-invoked, and its description was tuned on
2026-10-13 (trigger test 8/10, near-miss 0/10). The Phase 4 count on
2026-10-20 measured under-firing: the skill loaded in 3 of 16 real bug
sessions (19%), and in 1 of 3 bugs the person reported themselves. The plan
of 2026-10-13 says under half means a hook, so this plan adds one.

The hook gives deterministic control where the model may skip the skill
(Claude Code hooks guide, cited 2026-10-13). A nudge is advice, never a block.

## Approach

Add one advise-only amont-agent **assertion**, `bug-nudge`, that fires once
per session when a check runner fails and the skill has not been loaded.

It is an assertion, not a rule. A rule's `examine` sees only the command
before it runs, so it cannot see a result; assertions run after the tool.
This is a stated exception to the assertion admission test
(`assertions/mod.rs:15-18`, the failure must otherwise go unnoticed): a red
run is visible to the model, but skipping the skill is not, the same
reasoning as `publish-without-skill`.

- **Trigger, failed exit (Bash):** a non-zero exit arrives as
  `PostToolUseFailure` (`PostBashFailure`), never as PostToolUse. The exit is
  the signal, so no text match is needed. Register `bug-nudge` in both
  `ASSERTIONS` and `AFTER_FAILURE` (`assertions/mod.rs:97-104`).
  - Pipelines: with pipefail off (the zsh default), the exit is the last
    segment's. `cargo test 2>&1 | grep FAILED` on a green run exits 1 when grep
    finds nothing. So the exit counts as red only when the runner is the last
    segment. Otherwise the text must match in the failure's `error` field.
- **Trigger, exit 0 (PostToolUse):** a runner that exits 0 yet prints `FAILED`,
  `panicked` or `error[E`, for example a trimmed `cargo test | tail` without
  pipefail. Text match only.
- **Parsing:** `Bash` reads only `tool_response.stdout` today
  (`payload.rs:635-639`), and never `error`. Add `stderr` (cargo writes
  `error[E` and `panicked` there) and `error` to `Bash`.
- **Context:** `verify` sees only `Context` (`rules/mod.rs:366-393`), which has
  no output and no session id. Add `output: Option<&str>`, `session: &str` and
  `failed: bool` (true only in `on_post_bash_failure`, `src/hook.rs:491`; the
  doc on `Assertion::verify`, `assertions/mod.rs:93`, stops saying "only for a
  call that succeeded"), and fill all three at every constructor (`src/hook.rs:410`, `:491`, and the tests,
  check and backtest sites: 23 in total). `examine` stays the pure runner gate.
- **Runner gate:** `is_runner` from `test_output_trimmed.rs`, made `pub(crate)`
  and left unchanged. A new `is_check_run` wraps it and also accepts
  `amont run <check>` and `amont-agent quiet -- <runner>`. Extending `is_runner`
  itself would make test-output-trimmed fire on its own remedy. Applies to any
  pipeline segment on PostToolUse. A `grep` that prints "error" stays silent.
- **Order:** runner gate, then red, then the skill check, then the marker. A
  loaded skill never uses up the marker.
- **Skill already loaded?** `skill_window` for `diagnosing-bugs` over the
  transcript and the agent transcript. Current or Previous stays silent. An
  `Err` (unreadable, past 16 MB, truncated last line) stays silent. A payload
  with no `transcript_path` stays silent. `skill_window` covers only this turn
  and the one before, the window publish-without-skill uses.
- **Once per session:** a marker file keyed by session id only (subagents
  share it), at `journal::dir()/sessions/<session>.bug-nudge` after
  `usable_id`, created with `create_new` (after `create_dir_all` on `sessions/`)
  so parallel hooks cannot both nudge; any other `Err` stays silent.
  Separate from the file-op log in `session_state.rs`, which has no lock and
  is emptied by `compact`.
- **Message:** leads with "Call the diagnosing-bugs skill" inside the first 80
  columns (test copied from `publish_without_skill.rs`), then the rule it
  encodes: build a red loop before running more commands. The remedy reads as
  `publish_without_skill.rs:101-103` does: if the skill does not apply, ask the
  person; they can run `git config --global amont.agent.bug-nudge.stance observe`.
- **Stance:** advise, ceiling advise. It never denies.
- **Hook plumbing:** none new. `PostToolUseFailure` for Bash is already
  registered (`settings.rs:269`), so no re-install.

Reuse: `assertions/` (the post-execution shape); `is_runner` from
`test_output_trimmed.rs`; `skill_window.rs`; the message shape of
`publish_without_skill.rs`.

## Decisions for the person

1. **Success bar.** The backend and TUI reviewers agree a one-week count is
   too small: about 12 bug sessions a week, so one week rests on about six.
   Proposed: two weeks or 20 bug sessions, whichever comes later. The skill
   loads in at least half of them.
2. **Release.** A new assertion ships like 2.45.1: plan, PR, tag, brew. Whether
   to release now or wait for the measurement is the person's call.

## Verification

- `tests/hook.rs`: a `PostToolUseFailure` payload for `cargo test` (exit 101)
  with no `tool_response` produces exactly one advisory and no deny; the same
  payload again in the same session produces none.
- `tests/hook.rs`: a `PostToolUseFailure` payload for
  `cargo test 2>&1 | grep FAILED` with an empty `error` produces none.
- `tests/hook.rs`: a `PostToolUse` payload for `cargo test | tail` with
  `FAILED` in stdout produces one advisory.
- `tests/hook.rs`: a subagent payload whose agent transcript loaded the skill
  stays silent; an unreadable transcript, and a payload with no
  `transcript_path`, stay silent.
- `tests/hook.rs`: a `PostToolUseFailure` payload registers the assertion
  (`settings.rs` still registers the hook; a test asserts it).
- Unit tests for `is_check_run`: `amont run <check>` and
  `amont-agent quiet -- <runner>` match; `grep` that prints "error" does not.
- Message test: the nudge's first 80 columns name the skill.
- Backtest replay of 10-12..20 transcripts: firings on exit-0 runner calls
  outside the 16 bug sessions (expected near 0); the share of the 16 bug
  sessions where the nudge would have fired (target at least 13).
- Latency: a hook call on an 85 MB transcript stays within the precedent's
  140 ms forward read.
- `cargo test --workspace` and clippy with `-D warnings`.
- After release: the success bar in Decision 1, counted as in the 10-20 check.
  Under half reopens the plan.
